## Findings considered and rejected

These were surfaced during the audit and explicitly NOT turned into plans. Recorded so they aren't re-audited next session.

- **Sidebar projects list out of sync with main page** — Reported by a subagent. Rejected: `<NavProjects>` is actually commented out in `components/sidebar/app-sidebar.tsx:97`; there is no sync issue, just dead code. Dead code is addressed in plan 006 step H or plan 009.
- **Open redirect in `auth/callback?redirect_to=...`** — `${origin}${redirectTo}` string-concatenates rather than parsing; an absolute URL like `https://evil.com` becomes `https://site.comhttps://evil.com` and fails. Not currently exploitable. Worth migrating to a path-allowlist for defense-in-depth, but not a real-now finding.
- **`callbackUrl` open redirect in `forgotPasswordAction`** — `callbackUrl` is read from FormData but no form in the codebase submits this field; the conditional is unreachable in current UI. Latent risk if a future form adds it; flag in code review.
- **"24 Next.js advisories"** — Subagent over-reported by counting dev-only advisories. Actual `npm audit --omit=dev` against commit `296a6e5` shows 5 (1 critical, 2 moderate, 2 low). The critical is the only one warranting a dedicated plan (002); the rest are absorbed by plan 006 step E or follow-up dep maintenance.
- **`totalAmount` NaN risk** — Possible in theory but `projects.ratePerHour` is set via a Zod-validated number form; column is presumably `NOT NULL`. Not worth a plan absent schema evidence.
- **Missing CSP / security headers** — True but defense-in-depth for a personal-portfolio app with no sensitive UGC; not high leverage at the current stage. Revisit when the app handles untrusted UGC at scale.
- **Multiple useEffect race conditions / missing AbortController** — Generic React advice; no specific incident or symptom in this repo. Spec'ing a plan would be busywork.
- **Bulk operations on projects** (direction option C from the audit) — Speculative; no evidence of user demand or roadmap signal. Worth revisiting when there's user feedback.
- **Toggl / Harvest integration** (direction option D) — Same. No grounding in the repo.
- **Public API for vendor access** (direction option E) — Same. The Supabase client already constitutes a de-facto API for anyone with the anon key + RLS scope; productizing that needs strategic intent the audit can't supply.
- **Client portal analytics** (direction option F) — Same.
